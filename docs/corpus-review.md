# 语料巡检规矩

这份文档规定「怎么检查场景内容、怎么判、能改到什么程度、改完怎么处理音频」。
巡检对象是内容本身（`src/data/scenarios.json` 的台词、标题和中文译文）及对应音频一致性，不是界面或功能。

## 1. 检查项

按优先级从高到低。P0 必须立即处理，P1 当天或次日，P2 记录即可。

| # | 检查项 | 级别 | 怎么判 |
|---|---|---|---|
| 1 | 问答逻辑闭合 | P0 | 每一问都有回答；没有「问了却没下文」的对话；场景核心目标在台词里真的走完了 |
| 2 | 信息前后一致 | P0 | 人数、金额、时间、地点、星期、房型、尺码等，在同一个场景里前后不矛盾 |
| 3 | 中日一一对应 | P0 | 中文译文说的事与日语一致；不增不减、不反义、不把「可以」译成「不可以」 |
| 4 | 长度与结构 | P0 | 对话场景（`kind === 'dialogue'`）严格 **5–8 句**；短文场景（`kind === 'passage'`）严格 **5–6 段**；JLPT 听力（`kind === 'jlpt'`）严格 **4–12 句**；`category` 为 12 类有效值之一 |
| 5 | 日语自然度 | P1 | 是母语者在那个场合会说的话；没有翻译腔、没有教科书式生硬表达 |
| 6 | 助词、时态、敬语 | P0 | 助词搭配、时态（た形/ている/たことがある）、敬语层级与说话人关系匹配；严禁谦让语接「をお願いします」主客错位、严禁「こちらになります／〜円になります／どちらになりますか」等打工敬语、严禁二重敬语、同一说话人全段敬语层级一致 |
| 7 | 读音与数量词 | P1 | 数字、日期、量词、多音词按词典读法；重点核 三階(さんがい)、四時(よじ)、七時(しちじ)、九時(くじ)、一日(いちにち/ついたち)、三日(みっか)、二十歳(はたち) |
| 8 | 假名标注 | P1 | 按 W3C JLReq 标准：常规熟语逐字空格对齐 `{確認|かく にん}`，熟字训/当て字整词不分隔 `{今日|きょう}`，送假名与假名放花括号外，计数符号 `ヶ` 可标为 `{ヶ月|か げつ}`；标注读音准确，符合当前语境 |
| 9 | 重复与模板化 | P2 | 见第 4 节的「允许重复」与「实质重复」的界线 |
| 10 | 音色自洽 | P1 | 每个说话人在 `speakers[].voice` 按场景选定固定声线（可选 Gemini 官方 30 个预设音色）；同一场景内同一角色声线稳定不跳、不跨批拼凑 |
| 11 | 气泡与音频哈希一致 | P0 | 每句气泡纯日文文本与 `public/audio/manifest.json` 记录的 `voice + stripFurigana(ja)` 哈希严格一致；句数、顺序、文本与音频完全对应 |

### 1.1 书写与空格

- **自然连写，禁止人为空格**：`line.ja` 中不加分词空格（例如写 `{本|ほん}を{読|よ}みます`、`〜ています`，不要写 `{本|ほん}を {読|よ}みます` 或 `〜て います`）。
- 去掉人为空格可保证 iOS / 浏览器原生选中划词查词、复制与 Gemini TTS 韵律自然。
- `npm run check` 和 `npm run corpus:check` 会自动拦截日文正文中的多余空格。

## 2. 改的分寸

- **只修明确错误**：事实错、逻辑断、译错、读音错、标注错、多余空格、超出句数限制。
- **不改风格**：不因为「换个说法更好」而重写；不扩大改写范围。
- **不确定就标注**：拿不准的读音或表达先查证标记，不猜着改成确定结论。
- 参考源见 [`references.md`](references.md)（Irodori / Minato / NHK Easy / JMdict / OJAD / BCCWJ），只作核对，不抄原文。

## 3. 修改分 A、B 两类

这是保证「字幕与音频一致」的核心纪律。

**A 类：不改变音频哈希与朗读音色，可直接发布**

- 中文译文（`line.zh`、`titleZh`）
- 场景元数据（`emoji`、`accent`、`accentDark`、`category`）
- 标题（`title`）文字与标注调整（标题不参与逐句音频生成）
- 纯注音对齐调整（不改变 `stripFurigana(line.ja)` 纯日文正文）

**B 类：改变 `stripFurigana(line.ja)`（纯日文正文）或 `speaker.voice`，必须整场重生成音频**

- 台词纯日文正文的增、删、改
- 说话人变更、声线 `voice` 调整、句子顺序调整

> 说明：`public/audio/manifest.json` 对每句保存 `sha1(voice + '|' + stripFurigana(line.ja))`。只要改了纯日文正文或 `speaker.voice`，`npm run check` 会立即报哈希不一致，跑 `npm run tts`（短文跑 `npm run tts:passages`）会自动重新生成对应场景音频并刷新哈希。

**音色与整场一致性硬要求**：同一场景同一角色只能有一个音色，改字或改声线后必须整场（`--only=<id> --force`）重生成，不使用 `--line` 补正式音频。

## 4. 允许的重复 vs 实质重复

- **允许**：`ありがとうございます`、`わかりました`、`お願いします` 这类真实会话里的高频收尾句，跨场景重复不算问题。
- **不允许**：长度 ≥ 12 字、承载具体信息的句子在不同场景里整句复用（例如同一段用药说明出现在两个场景）。发现即改写其一并重生成该场音频。

## 5. 每轮怎么跑（先审后录，Agent 主动执行）

以后每次**新增场景**或**修改现有台词**，由 Agent 在合成 TTS 之前自动完成以下全部检查，不把人工校对留给用户：

1. **Agent 独立台本精读（在跑 TTS 前完成）**：
   - 运行 `node scripts/check-corpus.mjs --kana`，按**整句展开假名**与原文上下对照逐句通读（禁止只看去重后的孤立 `{漢字|かんじ}` 列表，以免漏掉送假名与语境错读，如 `{少|すこ}なめ`）
   - 逐句核对敬语主客一致、零打工敬语、零二重敬语、同一说话人全段语体统一、自然口语表达、问答逻辑闭环、中文译文准确对应、以及 JLReq 注音标准
   - 确认台本零问题后，再执行 TTS 合成
2. **跑自动语料巡检**：`npm run corpus:check`（重复、中文含假名、数量词/送假名读音、日文空格、句段数、`E8` 敬语与打工敬语红线）
3. **跑结构与音频哈希检查**：`npm run check`（结构字段、声线配置、JLReq 假名标注、句段数、音频文件、哈希一致性、孤儿音频）
4. 全部通过后，再执行 `npm run build` 发布。

## 6. 已知豁免

- 中文里用「」引用的日语词（如「お礼」）不算「中文含假名」。
- 短语级重复（见第 4 节）不报错。
